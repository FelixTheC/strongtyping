# Contributing

Thank you for your interest in improving `strongtyping`. Bug reports, documentation
improvements, tests, and pull requests are welcome.

## Before opening a pull request

1. Search the [issue tracker](https://github.com/FelixTheC/strongtyping/issues) for an
   existing report or discussion.
2. For substantial changes, open an issue first so the approach can be agreed on.
3. Create a branch from the current default branch and keep the pull request focused on
   one change.
4. Add or update tests for behavior changes, and run the relevant test suite and lint
   checks locally.
5. Describe the problem, the solution, and the validation performed in the pull request.

AI-assisted contributions are welcome when they are clearly disclosed in the pull request
and reviewed by the contributor for correctness, security, and licensing before submission.
The contributor remains responsible for the submitted change.

## Reporting bugs and requesting features

If a pull request is not appropriate, open an issue instead:

- Bug reports should include the `strongtyping` and Python versions, a minimal
  reproduction, expected behavior, and actual behavior.
- Feature requests should describe the use case, the current limitation, and a proposed
  API where possible.

## Code of conduct

Be respectful and constructive. Off-topic, abusive, or spammy contributions may be
closed.
